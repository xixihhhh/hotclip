# HotClip v0.32.1 — macOS bundle signature repair

- Repair the invalid macOS app resource seal reported in [#14](https://github.com/xixihhhh/hotclip/issues/14) by explicitly ad-hoc signing the application and nested binaries after packaging.
- Disable hardened runtime for these ad-hoc builds to avoid certificate team mismatches with bundled native libraries.
- Verify the complete macOS bundle signature and HotClip bundle identifier before uploading release assets; invalid signatures fail the release job.
- Add a [macOS installation guide](https://github.com/xixihhhh/hotclip/blob/v0.32.1/docs/macos-install.md) with first-launch instructions, signature verification, and a scoped quarantine workaround for trusted downloads.

The macOS app is **not Apple-notarized** and has no Developer ID certificate. Gatekeeper can still block the first launch. Ad-hoc signing repairs bundle integrity; it does not establish Apple trust or remove the need for a manual first-launch exception.
